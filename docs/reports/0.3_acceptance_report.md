## 三、Tier I 风冷算力机柜 `air_cooled_compute_rack`

- **结构**：固定 3×5×2 多方块（`start(RIGHT, UP, BACK)`）：进风面外墙（含主控）+ 出风面外墙（中排为能源仓×1–2 / 维护仓 / **GTCEu 原生 `gtceu:computation_transmitter_hatch`** 精确 1），外观块＝进风面外壳，主控模型＝进风面贴图 + `overlay_front(.active)`。
- **刀片槽**：4 槽 GUI（`CustomItemStackHandler` 过滤刀片）+ 零食槽；每枚刀片 6 CWU/t，**0→24 CWU/t 线性**（GameTest 逐枚插拔断言）；空槽 0。
- **原生 CWU 供能**：主控实现 `IOpticalComputationProvider`（与原版 HPCA 同构），经 GT 光学管道 + 原生传输仓向消费者供算。
- **严格同 tick 算力预算**：`requestCWUt(cwut, simulate)`：
  - `simulate==true` 只查询不扣减（GameTest 断言预算保持 0 扣减、真请求记账 20）；
  - 真实分配受单 tick 剩余预算约束：同 tick 消费者 A 取 20 后 B 只得剩余 4、第三次请求 0；预算窗口以 offset timer 惰性翻转（先到先得、不跨 tick 重复扣减）。
  - **降额归零**：低电（能源仓抽干）/未维护（维护位归 0）/软锤暂停/无刀片 → 供算归零并记录 `DerateReason`（GameTest 三态逐一断言）；断光缆 → 消费端拿到 0（GameTest 换石头断缆验证）。
- **区块卸载/重载**：BE 全量 NBT 往返后刀片、零食槽、结构保持，预算窗口换新后仍可满额分配（GameTest 断言）。

## 四、光学链路对原版 `gtceu:research_station` 稳定供算 + HPCA 共存

- GameTest `opticalLinkFeedsResearchStation` **搭出真实科研站多方块**（3×7×7：计算机机壳/散热格栅/高级计算机机壳 + 原生 `computation_receiver_hatch` + UHV 能源仓 + 维护仓 + 对象支架朝南），用 GT 光学管道（机柜原生传输仓 ↔ 站原生接收仓，显式 `setConnection` 连接）连续 6 个采样 tick 经 `station.getComputationProvider().requestCWUt(24, false)` 拿满 24 CWU/t；断缆（管道换石头）后供算即刻归 0，机柜侧预算不受影响。
- GameTest `hpcaCoexistence` **搭出真实 HPCA**（2×5×5 + 1× 计算组件=4 CWU/t + UV 能源仓 + 维护仓 + 传输仓）：同 tick 内 HPCA 独立供 4 CWU/t、我方机柜独立供 24 CWU/t，互不扣减对方预算（断言机柜 `allocatedCWUt` 与 HPCA 请求无交叉）。
- **实测校准发现（数值口径）**：原版唯一科研站配方（network_switch 科研，`totalCWU` 模式）需求 **32 CWU/t**（VA[7] EU/t），高于单台 Tier I 机柜的 24 CWU/t——与实施计划「先实测科研需求再定 CWU/t 梯度」的约定一致；单机柜仅供算、不驱动该配方跑完，双机柜/科研站聚合（原生 network_switch 路径）留给后续版本。供算链路本身（24 CWU/t × 连续 tick）已被上述测试完整验证。

## 五、Tier II 精密空调 `precision_crac` 与有限范围 PUE 结算

- **结构**：固定 3×3×1 多方块（IV 机壳 + 能源仓 + 维护仓），主控模型＝GT IV 机壳贴图 + `overlay_front(.active)`；运行耗电 128 EU/t。
- **PUE 结算**（机柜主控内，`DatacenterRating` 纯函数 + 实机双断言）：
  - `总耗电 = IT 耗电 + 基础制冷耗电 × 环境系数 × 气流系数`，`PUE = 总耗电 / IT 耗电`，IT=0 时界面显示待机 64 EU/t；
  - 满载 4 刀片：IT=1024，基础制冷=0.8×IT；**Tier I 气流系数 1.00 → PUE≈1.80**（总 1843 EU/t）；**Tier II 气流系数 0.5625 → PUE≈1.45**（总 1485 EU/t）；
  - **环境冷源**：冰原/雪山（降水 SNOW）/深海群系或 `Y<20` → 制冷 ×0.6（GameTest 世界低于 Y20，实测 Tier I PUE=1.48、Tier II=1.27，中性环境 1.80/1.45 由纯函数断言）；下界维度 ×2.0、热沙漠（无降水且均温 ≥1.5）×2.0；
  - **零食包彩蛋**：槽位配备零食 → 全机房总耗电 -5%（`DatacenterConfigs.snackPackBonus` 开关）。
- **Tier I→II 升级条件**（全部为有限范围、事件驱动，禁止每 tick 扫描）：
  1. 机柜足迹正下方 3×2 全铺 `raised_floor`；
  2. 进/出风中心通道未堵死（前后中心格非实心，邻近方块变化即时触发重评）；
  3. 8 格范围内有**运行中**的 `precision_crac`（机柜成型全量有界扫描 + CRAC 成型/失效/运行翻转反向通知 + 40 tick 有界缓存校验）。
  - GameTest：裸机房 Tier I（1.48 冷源口径）→ 铺地板 + CRAC 供电运行 → Tier II（1.27）→ 堵进风口 → 回落 Tier I；`dimensionMultiplier(NETHER)=2.0`、`Y<20` 冷源系数与 1843/1485/1515 EU/t 数值逐项断言。

## 六、推理协处理器仓 `iv_inference_hatch`（真实消耗 CWU/t）

- **形态**：IV 级多方块仓室部件（GT 原生光学算力接收链路 `OpticalComputationHatchMachine(receiver)` + 推理芯片槽），注册自有 `PartAbility inference_computation`，数据清洗塔结构可选接受（≤1）。贴图 `overlay_front(.active)`，运行态随主控状态自动切换。
- **白名单验证路径**：两条数据清洗基准配方打上 `hc_inference_boost` 标签：
  - 芯片：普通矿处/化工边缘芯片 → **2 CWU/t，EU/t -25%**（2048→1536）；已对齐芯片 → **8 CWU/t，EU/t -50%**（2048→1024）；
  - `modifyRecipe` 命中白名单 + 芯片可承接 + 模拟请求成功 → 改写为「+CWU/t 逐 tick 输入 + 折扣 EU/t」，此后每 tick 经推理仓原生计算容器真实计费（与科研站同一条原生管线）；
  - 算力不足/无芯片/断缆 → 配方原样通过（原 2048 EU/t、零计费）；**运行中断算** → 逐 tick 结算失败 → 等待 → 看门狗中断卡住的批次 → 下一批按原规则继续（不白嫖、不永久卡死）。
- GameTest `inferenceHatchConsumesRealCwu`：机柜+管道+推理仓+芯片全链路下基准清洗配方以 **1536 EU/t** 运行、配方带 2 CWU/t 需求、机柜预算每 tick 记账 2；拔刀断算后新鲜日志批次以 **2048 EU/t** 原规则跑完并产出高纯矿处数据集（断言无 CWU 计费、机柜可供算归 0）。
