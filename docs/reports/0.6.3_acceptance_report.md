## 1. 音效接入

### 1.1 素材恢复

任务单所述 `Public/sounds/` 下 8 个 `.ogg` 在基线工作区中并不存在。经排查，其**无损 PCM 母带仍完好**保留在合成脚本的中间产物目录（`wav_tmp/*.wav`，`pcm_f32le`、mono、44100 Hz，已完成全部 DSP 处理与 LUFS 迭代归一）。

按合成脚本 `encode_ogg()` 的原始参数重新编码，不做任何再合成：

```
ffmpeg -ac 1 -ar 44100 -c:a libvorbis -q:a 6.0
```

重新编码逐样本等价于原版（差异仅来自 Vorbis 编码器版本）。8 个文件全部符合规格：

| 文件 | 时长 | LUFS | True Peak |
| --- | --- | --- | --- |
| `datacenter_air_hum.ogg` | 5.00 s | −13.9 | −1.8 dBTP |
| `datacenter_liquid_hum.ogg` | 5.00 s | −14.0 | −1.8 dBTP |
| `pretraining_cluster.ogg` | 6.00 s | −14.0 | −2.0 dBTP |
| `satellite_uplink.ogg` | 5.00 s | −14.0 | −2.0 dBTP |
| `laser_burn.ogg` | 4.50 s | −14.0 | −1.9 dBTP |
| `red_team_scan.ogg` | 5.00 s | −14.0 | −2.4 dBTP |

全部 mono / 44100 Hz / Ogg Vorbis，目标 −14.0 LUFS 命中，真峰值均 ≤ −1.2 dBTP，无削波。

### 1.2 代码接入

| 文件 | 作用 |
| --- | --- |
| `common/data/HyperClusterSounds.java` | 8 个 `SoundEntry` 定义与注册，`SoundSource.BLOCKS`，循环音衰减 24 格、单次音 16 格 |
| `HyperClusterAddon#registerSounds()` | 在 GTCEu 冻结 `GTRegistries.SOUNDS` **之前**注册（`GTSoundEntries.init()` 调用该钩子） |

`sounds.json` 由 datagen 生成在 `src/generated/resources/assets/hypercluster/sounds.json`，**注册表与 JSON 不可能漂移**。

### 1.3 绑定实现

**配方驱动的 4 台**（走 GTCEu 原生 `RecipeLogic#updateSound`，机器停止/卸载时由框架自动停播）：

| 机器 | 配方类型 | 音效 |
| --- | --- | --- |
| `hv_micro_burner` | `MICRO_BURNER_RECIPES` | `laser_burn` |
| `lora_engraving_chamber` | `LORA_ENGRAVING_RECIPES` | `laser_burn` |
| `red_team_sandbox` | `RED_TEAM_TESTING_RECIPES` | `red_team_scan` |
| `tensor_pretraining_cluster` | `TENSOR_TRAINING_RECIPES` | `pretraining_cluster` |

**运行 `DUMMY_RECIPES` 的 3 台**：其"工作"是 tick 契约而非配方，`RecipeLogic` 永远报告 IDLE，原生音效钩子不会触发。改用**同一个 `AutoReleasedSound` 类**显式驱动：

| 机器 | 音效 |
| --- | --- |
| `air_cooled_compute_rack` | `datacenter_air_hum` |
| `liquid_cooled_compute_rack` | `datacenter_liquid_hum` |
| `api_satellite_station` | `satellite_uplink` |

谓词与 GTCEu 自身守卫一致：`shouldWorkingPlaySound()`（尊重 GT 机械音效开关与消音升级）、`!isInValid()`、`level.isLoaded(pos)`、`MetaMachine.getMachine(level,pos) == machine`。`AutoReleasedSound` 每客户端 tick 轮询谓词，为 false 即自我释放——**停止与卸载由框架负责**。全程不直接触碰音频设备，Blocks 音量归零时安全静音。

**单次触发**：

- `rack_click` — 挂在部署槽与 4 个 LoRA 槽的 `onContentsChanged`（覆盖手动 / 管道 / AE2 三条插拔路径），以及路由状态切到 LOADING/ONLINE/EVICTED 时。
- `terminal_alert` — 5 个告警源统一走 `MachineAlerts.play(...)`，同机 60 tick 节流：
  - 429 限流 → `ApiSatelliteStationMachine#updateRenderStateFor`（`RATE_LIMITED_429`）
  - 503 拥塞 → `OpticalFabricSwitchMachine#setStatus`（进入 `BUSY_503`）
  - OOM → `MoeRouterRackMachine#playStateCues`（`State.OOM` / `EVICTED`）
  - 冷却断供 → `LiquidCooledComputeRackMachine#settleTick`（首次进入 `NO_COOLANT`）
  - UPS 切备电 → `UpsPowerArrayMachine#discharge`（本次停电首次放电）

## 2. MoE 路由器 6×6 发光大屏

### 2.1 结构不变性

`MOE_ROUTER_RACK` 的 `FactoryBlockPattern` **一字未改**，仍是 `5×5×5`。屏幕是纯客户端四边形，不占方块，`TopologyTests` 与全部存档不受影响。

### 2.2 实现

| 项目 | 实现 |
| --- | --- |
| 渲染器 | `client/renderer/MoeScreenRender.java`，继承 GTCEu `DynamicRender`（7.4.0 的实际扩展点；`IDynamicRender` 在该版本已更名为 `DynamicRender` 抽象类） |
| 挂载 | `HyperClusterMachines` 用 `.model(createWorkableCasingMachineModel(...).andThen(b -> b.addDynamicRenderer(MoeScreenRender::new)))` |
| 类型注册 | `HyperCluster#registerDynamicRenders()`，幂等守卫；datagen 与客户端共用同一注册路径 |
| 贴图 | `assets/hypercluster/textures/screens/whale_maid_screen_96.png`（96×96） |
| 尺寸 | 6×6 方块 × 16 px/格 = **一像素一纹素 1:1**，无过滤 |
| 位置 | 居中悬停于顶框上方：控制器中心 → 屋顶（+3.5）→ 悬空 0.75 格 |
| 亮度 | `LightTexture.FULL_BRIGHT`，`RenderType.entityCutoutNoCull`（双面可见，透明边缘不画黑框） |
| 朝向 | 随 `getFrontFacing()` 四水平向旋转（`RotationState.NON_Y_AXIS`，无上下朝向） |
| Z-fighting | 面板悬在开放空气中，其平面内无其他几何体 |
| 剔除 | `getRenderBoundingBox` 覆盖 6×6 悬浮区（±7 格水平、+14 格垂直）；`shouldRenderOffScreen=true` 防随控制器区块段剔除 |
| 点亮条件 | `isScreenLit()` = 已成型 ∧ 未失效 ∧ 有电 ∧（部署 `deepseek_v6767*` ∨ 手开开关） |
| GUI | 主控新增"展示大屏"开关（`ToggleButtonWidget`，x=36），与现有 DeepThink 开关间隔 4 px |
| 持久化 | `@Persisted @DescSynced boolean showScreen` |

### 2.3 与任务单的一处措辞说明

任务单写的是"注册到 `MultiblockMachineDefinition` 的 `dynamicRenderer`"。GTCEu 7.4.0 中该 API 的实际形态是 `MachineModelBuilder#addDynamicRenderer(Supplier<DynamicRender>)`，经 `MachineBuilder.ModelInitializer` 挂载——即上述写法。功能等价。

## 6. 已知限制

1. **大屏画面未经实机目视验证。** 冒烟测试只到主菜单，未进入世界并在游戏内成型 MoE 路由器观察屏幕的朝向、位置与亮度。渲染逻辑（URL 编码、朝向、AABB、点亮条件）均有 GameTest 覆盖，但**像素级观感未验证**。
2. **`Doc` 中 `IDynamicRender` 名称**：任务单使用的接口名在 GTCEu 7.4.0 中不存在，实现改用同职能的 `DynamicRender` 抽象类。
3. **`terminal_alert` 的 UPS 与 503 触发**：接线完成并由 `MachineAlerts` 统一节流，但未针对这两个触发源单独写断言（现有用例覆盖 OOM 路径与节流逻辑本身）。
4. **音效实际听感未验证**：文件规格（LUFS / 峰值 / 时长 / 容器）已逐项校验，但未在游戏内实际聆听循环接缝与响度平衡。
