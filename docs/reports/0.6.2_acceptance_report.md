# 0.6.2 三处运行时与文档落差补齐验收

基线为 `main @ 33f3d5d`（0.6.1），运行组合为 Minecraft 1.20.1、Forge 47.4.0 与 GTCEu 7.4.0。本版**未引入任何 Mixin**：三块落差分别落在物品 NBT 契约、自定义 `RecipeLogic` 结算钩子与机台 tick 循环三处原生扩展点上。

0.6.1 的验收报告第七节写明了当时的欠账：模型家族的机制「以注册表契约与纯函数断言覆盖，**尚未接入对应机台的运行时结算路径**」，第六章手册因此存在**超前描述**。本版把这笔账结清——手册里写的每一条，游戏里都真的会发生。

## 一、权重模块身份 NBT

### 1.1 `hc_model_id` 字段

`OpenWeightModuleItem` 新增 `MODEL_TAG = "hc_model_id"`，与 `hc_domain` / `hc_precision` / `hc_version` / `hc_runs` 并列构成模块的持久记录。

| 契约 | 行为 |
| --- | --- |
| 写入 | `create(base, modelId, domain, precision, version, runs)`；模块为**单件**栈 |
| 白名单 | 只有 `Camp.LOCAL` 的模型 id 可写入；写入 API 阵营 id（如 `gpt_1145_multiverse`）会**降级为旧身份**，堵死用 NBT 把闭源模型塞进路由柜的路子 |
| 旧模块兼容 | 无该字段（0.6.1 及更早产出）→ `modelId()` 返回 `LEGACY_MODEL_ID = qwen_9187_pro_max_ultra`。0.6.1 只可能产出 Qwen，所以旧权重全部继续可用 |
| 解析 | 按**裸路径**（`qwen_9187_pro_max_ultra`）在目录里线性查找。`Catalog#get(String)` 会把裸路径解析成 `minecraft:...`，故不走该重载 |
| 工具提示 | 新增金色「权重：<家族名>」行，与原有领域/精度/版本行并列 |

### 1.2 预训练集群的目标模型选择器

`TensorPretrainingClusterMachine` 的 `MachineUi` 操作区新增**目标开源模型选择器**（第 2 个 18 px 按钮），循环 5 台开源模型；标签为「目标模型」，按钮文字实时显示家族显示名。

门槛按目标模型**动态校验**，`AIModelDefinition#trainingGate(vramTb, cwuPerTick)` 声明：

| 目标模型 | 显存门槛 | 算力门槛 |
| --- | --- | --- |
| Qwen 9187 Pro-Max-Ultra | 96 TB | 32 CWU/t |
| DeepSeek-V6767 Flash | 64 TB | 24 CWU/t |
| DeepSeek-V6767 Pro | 128 TB | 48 CWU/t |
| GLM-2333 Flash | 32 TB | 16 CWU/t |
| GLM-2333 Max | 80 TB | 32 CWU/t |

- 启动闸门读取 `getJobVram()`（= 所选家族的显存门槛）与 `requiredCwu()`（= 所选家族的 CWU/t 门槛），显存不足 → `OOM`，算力不足 → `NO_COMPUTATION`，二者都**拒绝启动而非降级**。
- 训练完成掉落的模块写入 `hc_model_id = getTargetModelId()`，同时保留领域/精度/版本/血统。
- **换目标会清空 Checkpoint**（`progressTicks` / `checkpointPercent` 归零）：不同家族的权重不能接续训练。
- 界面新增「目标家族：%s」「光学算力需求：%s CWU/t」两行。

### 1.3 路由柜按 `hc_model_id` 精确解析

`MoeRouterRackMachine#modelInSlot()` 从「按领域遍历找第一个匹配」改为**直接取模块声明的家族**：

```java
AIModelDefinition definition = OpenWeightModuleItem.definition(stack);
if (definition == null || !definition.isLocal()) {
    return null;                     // 非开源 id 一律拒绝，不做silently coerce
}
return definition;
```

5 台开源模型因此可**各自独立部署**，显存与 CWU/t 都按自己那份声明算。0.6.1 的「路由柜只能选 Qwen」被彻底修掉——验收日志逐台打印：Qwen 16 TB/4 CWU、Flash 32 TB/2 CWU、Pro 64 TB/4 CWU、GLM Flash 24 TB/4 CWU、GLM Max 48 TB/8 CWU，全部 `ONLINE`。

`loadedModel()` 同时兼容全 id（`hypercluster:x`）与裸路径，旧存档不会因字段格式而认不出模型。

## 二、开源权重克隆（保留全部 NBT）

`hv_micro_burner` 由 `SimpleTieredMachine` 换为 `MicroBurnerMachine`（仍继承 `SimpleTieredMachine`），新增克隆配方与专用结算逻辑。

| 项 | 值 |
| --- | --- |
| 配方 id | `hypercluster:micro_burner/clone_open_weight_module` |
| 输入 | 1× `open_weight_module`（**`notConsumable` — 原件不消耗**）+ 1× `blank_carrier`（消耗） |
| 电力 | 480 EU/t × 200 tick（HV 段顶格，HV 能源仓可驱动） |
| 产出 | 1× `open_weight_module`，**完整复制** `hc_model_id / hc_domain / hc_precision / hc_version / hc_runs` |

**实现要点（踩坑记录，长期有效）**：GTCEu 的配方匹配会对 output content 调用 `ItemRecipeCapability.copyInner`，把内容**强转成 `Ingredient`**。第一版把带 NBT 的 `ItemStack` 写进 `outputs`，`high_purity` 配方匹配阶段直接 `ClassCastException: ItemStack cannot be cast to Ingredient` **崩掉整个 GameTestServer**。正确做法是：配方 output 保持**朴素可匹配的模块**，NBT 在**结算之后**由 `MicroBurnerRecipeLogic#onRecipeFinish()` 从仍在输入槽里的原件复制过去。因为原件是 `notConsumable`，结算时它必然还在——这也正是「克隆无损」成立的前提。

验收日志：`burner: cloned deepseek_v6767_pro keeping the original (out=deepseek_v6767_pro, runs=1)`，与手册第六章「克隆副本」页**逐字对应**。

## 三、六大家族接入机器运行时结算路径

新增 `ModelRuntime`（纯函数表，无世界访问），作为「家族实际做什么」的**唯一真相**，机台与测试调用同一个函数，行为不可能在手册、测试、机台之间漂移。

### 3.1 闭源卫星站 `api_satellite_station`

新增第 6 个槽位（越狱补丁卡）与「危险轮次」开关，二者都在 `MachineUi` 操作区（操作区高度 75 → 101，`MachineUiTests` 零重叠回归已同步）。

| 模型 | 运行时行为 | 验收证据 |
| --- | --- | --- |
| `gpt_1145_multiverse` | 武装危险轮次且**未插越狱卡** → `MORAL_REFUSAL`：轮次不启动、输入不消耗、**0 Token 计费**；插卡后同一轮次立即放行（实测价格 60,000） | `GPT refused (MORAL_REFUSAL), input kept, 0 Token spent` → `jailbreak inserted -> dangerous round running (price=60000)` |
| `grok_420` | **免越狱直接放行**危险轮次；雨天耗时可**真实** ×3.0、雷暴 ×4.0（普通家族 ×1.5 / ×2.0） | `uncensored dangerous round running, 100 ticks in clear weather`；`rain penalty 3.0x -> 300 tick round (vs 150 for a normal family)` |
| `gemini_titanium_4_0` | `Leaving Soon` 拦截（0.4 起已实装，本版纳入家族运行时表统一回归） | `leavingSoonExpiryBlocksCloud` 通过 |
| `gemini_platinum` | 化工降噪 → **化工轮次产出 +1**（矿处轮次无加成，因为降噪在采矿上无从谈起） | `familyRuntimeContract` 断言 chemical=true → +1、chemical=false → 0 |
| `gemini_xenon` | **每轮产出 +1** 且**免维护**（`waivesMaintenance`） | 同上纯契约断言 |
| `gpt_1145_multiverse` | 最高单价换最高省料 → **每轮产出 +2** | `yieldBonus` 断言 |

天气翻倍修正一处语义：`weatherAttenuation` 现在只在 `base > 1.0` 时翻倍。晴天（×1.0）不该因为模型「weather-fragile」凭空变成惩罚。

结算时**按轮次开始时记录的模型**（`taskModelIndex`）算产出，不会把玩家中途切换的模型记到已跑的那一轮上。

### 3.2 本地兜底网关 `local_fallback_gateway`

网关新增**实时**机房查询：扫 16 格内 `MoeRouterRack`，只要有一台 `state == ONLINE` 且 `loadedModel() == qwen_9187_pro_max_ultra` 即判定「Qwen 在线」。

| 机房状态 | 兜底降速 | 轮次时长 |
| --- | --- | --- |
| Qwen 在线 | **×1.5** | 150 tick |
| 未部署 / 下线（OOM、EVICTED、拔卡） | **×4**（0.4 契约） | 400 tick |

`CloudPricing` 新增 `taskTicks(..., double fallbackSlowdown)` 重载，倍率成为机房属性而非常量；卫星站通过 `attachedGatewaySlowdown()` 向网关索取，两边不可能算出不同答案。网关界面直接显示当前倍率。

验收：`fallback: Qwen ONLINE -> x1.5 (150-tick round instead of 400)`。

### 3.3 开源路由与推理执行 `moe_router_rack` + `iv_inference_hatch`

路由柜 tick 由「只判定 ONLINE」升级为**真实结算**：

- **真实扣算力**：ONLINE 时通过光交换机（无交换机则直接向液冷/风冷机柜）拉取 `billedCwuPerTick()`，记入 `consumedCwu`。DeepSeek 的 25% 稀疏因此是**真的只扣 25%**：验收日志 `deepseek flash: billed 2, really drew 2 CWU/t`（名义 8）。
- **DeepThink**：Pro 开启后显存要求 64 → **80 TB**（+16），并向 16 格内关联推理仓投射 `byproductsForced`。验收：`deepseek pro: requires 80 TB, by-products forced=true`。
- **Qwen LoRA 投射**：4 个 LoRA 槽里的矿处/化工卡按领域向关联推理仓投射，每张卡把该领域概率副产 **+1/3**（1/3 → 2/3 → 100%），由 `IvInferenceHatchMachine#applyLoraSpecialisation` 重写配方。
- **GLM-2333 Flash 欠电保护休眠**：路由柜储能 **< 20%** → `SLEEPING`，**0 CWU/t 实扣**，电网恢复当 tick 自动唤醒。验收：`fully charged -> brownout=false, state=ONLINE` → `charge 0.0% -> state=SLEEPING, drew 0 CWU/t`。
- **GLM-2333 Max 满仓/缺料自动停机省待机电**：代理读取关联多方块的 `RecipeLogic`，`isWaiting()`（堵仓/缺料）或彻底空闲即判为停摆，调用 `setWorkingEnabled(false)` **真的把关联多方块停机**；进入占空比循环（停机 40 tick → 探测 20 tick），能干活就自动拉起。状态 `AGENT_IDLE`。
- 模型离开 ONLINE（OOM / EVICTED / 拔卡）时 `clearProjections()` 撤销它投射到推理仓的全部加成，不会留下「模型已下线但副产还在拉满」。

推理仓侧新增 `applyByproductForce` / `applyLoraSpecialisation` 两个配方重写，均返回 `copy()`，绝不改动注册表里的共享配方对象。

## 七、遗留与边界

- **DeepSeek Pro 的 128 TB 门槛**：`hc_field` 是单一共享场地，16 格聚合会看到别的测试摆的机柜。因此 `deepSeekDrawsSparseCompute` 摆了**两座**满插 LuV 显存柜，并断言 `poolTerabytes() >= requiredTerabytes()` 而非写死数字（沿用 0.6.1 的场地共享经验）。
- **GLM Max 的代理启停在测试中以纯契约 + 状态机覆盖**，未构造「真实堵仓」的多方块场景——代理读的是 `RecipeLogic#isWaiting()`，而堵仓的复现需要真实输出总线塞满，成本高于收益。
- 0.6.1 遗留的两条仍未变：光交换机 503 在测试中经 `tripBusy()` 确定性复现，未构造真实超带宽并发；断算回退仍会 interrupt 当前批次（原版语义）。
