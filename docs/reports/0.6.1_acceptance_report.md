## 二、TB 显存体系

- **刀片脱钩**：`luv_liquid_blade` 不再提供显存（`VRAM_PER_BLADE = 0`），算力与内存彻底分账。
- **独立显存硬件**：`iv_hbm_module` 4 TB/条、`luv_hbm_module` 16 TB/条；显存机柜 4 槽，满插分别为 **16 TB** 与 **64 TB**。
- **训练门槛**：`tensor_pretraining_cluster` 的 OOM 门槛抬到 **96 TB**，即两座满插 LuV 条的显存机柜（128 TB），或 1 LuV + 2 IV 压线。
- 显存必须**在线**才计入池：拔模块、维护未修、软锤暂停、断电都会当 tick 把该柜 TB 移出池子。

## 六、验收期修正

实机截图发现一处**单位漂移**：显存机柜已显示 `64 TB`，但预训练集群仍写 `在线 64 GB / 需要 96 GB`。数值本身正确（64 与 96），纯粹是 0.6.0 遗留的 `GB` 标签没跟着迁移。已修正 7 处：

- `tensor_pretraining_cluster.vram` zh/en 改为 **TB**（用户报告的那处）；
- `luv_liquid_blade` 物品 Tooltip 与液冷机柜刀片槽说明**删除了「24 GB 显存」**——该值在 0.6.1 已是 0，属于内容错误而非单位问题；
- 删除算力机柜已无意义的 `vram` 显示行与翻译键（避免显示恒定 0）；
- 清理 Java 注释与测试消息中的 GB 表述。

新增回归 `vramLabelsUseTerabytesOnly` 守住这条：任何显存标签出现 `GB` 即失败。
